**R3+R6 分项证据提取契约（codex 阻断项 1：固定命令 + 权威行 + 落盘，逐条机器可判定）**：

1. **为什么必须显式传 `--iterations 5`**：脚本默认 `ITERATIONS=3`（`tools/run-dmabuf-regression-test.sh:40`），不显式传参则权威行输出 `rounds=3`，与 4.0.2-i3 既有先例的 **5/5** 口径（`docs/planning/evidence/4.0.2-i3/run-test-results.txt:25`：`sudo 复跑：5/5 + kernel_log=clean`）不一致。本方案取**显式传 `--iterations 5`**（选项合法值 `^[1-9][0-9]*$` 且 ≤100，:72-74/:89），保持与 4.0.2-i3 同口径；**不得**改判为 3/3，也**不得**保留「5/5 判定 + 默认 3 轮命令」的矛盾组合。
2. **R3 权威行（唯一判定来源，取脚本 stdout）**：

   ```
   dmabuf_self_import=PASS reason=rounds=5-fd_cloexec=yes-fd_leak=no-fds=<n>-><n>-device=1ec8:9810
   ```

   该行由 `record_pass`（:350）在 :418 输出，**`rounds=5` 即 5/5 语义**——脚本在输出 PASS 前已强制校验：header `iterations=5` 与本次运行一致（:376/:383）、round 行 1..5 无缺失无重复无越界（:392-403）、`summary self_import rounds=success=5 failures=0`（:375/:413-414）、fd 数前后不变且 `fd_leak=no`（:416-417）。任一不满足 → 输出 `dmabuf_self_import=FAIL reason=…`，此时 R3 记 fail，**不得**以整体行或 rc 反推 R3 通过。
3. **R6 权威行（唯一判定来源，取脚本 stdout）**：`dmabuf_vblank_inactive_guard=<PASS|SKIP|FAIL> reason=…`，状态机：

   | 权威行 | R6 status | 依据 |
   | --- | --- | --- |
   | `=PASS reason=inactive_crtcs_tested=<N>-all-einval-fast`（:739） | **pass** | inactive CRTC 实测 EINVAL 快速返回 |
   | `=SKIP reason=no_inactive_crtc`（:770，无 inactive CRTC 时既有行为） | **n-a** | closed/evidence/basis/approval 四项必填（§四 n-a 条件）；**不得**判 pass 或 fail |
   | `=FAIL reason=inactive_crtcs_tested=<N>-ok=…-failed=…`（:737） | **fail** | closed=false，阻塞签发 |

   注意：整体行 `dmabuf_regression_overall=PASS` **不因 SKIP 而降级**（:871-873 明确「SKIP 不阻止整体 PASS」），故**禁止**用整体 PASS 推导 R6=pass；R6 只认上表权威行。
4. **证据落盘（强制）**：脚本在输出 overall 前 `rm -rf` 自身 runtime 临时目录（:848，另有 :310 早退清理路径），逐探针中间产物（`self-import.out` 的 header/summary 行等）**不保留**。因此真机批必须把脚本 **stdout+stderr 整体重定向落盘**到 `docs/planning/evidence/o-stage/runtime-5.0.0-i1/dmabuf-aggregate.txt`，R3、R6、`o-stage-integrity` 三个条目的 evidence 均引用该文件（含行号）；未落盘 = 无证据 = 三项均未闭合。
5. **夹具命名空间排除（强制）**：权威行**必须**无 `fixture_` 前缀且 reason **不含** `-mode=fixture` 标记（:109-112：夹具模式改写 `NS` 与 `tag`）。真机运行不得设置 `INNOGPU_DMABUF_FIXTURE_MODE` 或任何 `FAKE_*`/`INNOGPU_DMABUF_*` 注入钩子（:24-33）；出现夹具标记的输出**一律不得**作为 R3/R6/o-stage-integrity 的权威行。
6. **其余子项归属**：invisible read / write-readback / topology(active vblank) / 设备身份 / 状态快照 / 内核日志门禁 / 子项计数 / 整体行 → 全部归 **`o-stage-integrity`** 条目，其权威行表与合并规则见 §四；**整体 rc 与 overall 行不直接替代 R3/R6 任一单项结论**，反之亦然。

**R7-R9 证据格式（F5 输出契约，固定）**：

- connector 段：每 connector 一行 `connector <id> <name> status=<connected|disconnected> modes=<count>` + 全部 mode 行 `<hdisp>x<vdisp>@<vrefresh>`；

```
3. 重启 → fantgpu 模块加载确认（modinfo/vermagic 记录 + 指纹采集：build-id/对象 SHA → 注入 R5 参数）
4. R1 / R2 / R4 探针（DRM 基础能力 + fbdev mmap **生产构建**探针 + VA-API 解码）
5. R3+R6+o-stage-integrity：**单次** `run-dmabuf-regression-test.sh --iterations 5` 聚合运行（stdout+stderr 落盘 `dmabuf-aggregate.txt`；三条目同源于此一次运行）；随后 R7-R9 topology 探针
6. R5 suspend/resume + U1/U2 观察（系统风险项放后段）
7. rollback → 恢复安装前状态 → 恢复验证
8. validation-results.json 填充（§四 **必填条目清单全量**：R1-R9 + U1/U2 + install-rollback + `o-stage-integrity`；materialize_meta_sha256 校验一致后方可填结论）
9. 三方一致 + dsh 终审 + 用户批准 → 签发 fantgpu-5.0.0-i1
```

依赖：0.5 依赖 0；1-9 依赖 0.5；4-9 依赖 3；7 依赖 4-6；8 依赖 7。**install/rollback 往返为真机阶段最后闭环**（安装是最先动作、回退是最后动作）。**R3、R6、`o-stage-integrity` 三条目必须同源于步骤 5 的单次聚合运行**——不得分次运行拼凑证据（分次运行会使 `--iterations`、状态快照前后对比与内核日志窗口失去同源性）。

## 四、证据落点与签发状态机（codex P1：闭合字段机器可执行）

- `docs/planning/evidence/o-stage/5.0.0-i1-validation-results.json`（schema `validation-results-1.0`）：
  - `materialize_meta_sha256`：= `5.0.0-i1.meta.json` 的 SHA-256——验证阶段先校验与不可变 meta 一致，一致后方可填充结论（单向绑定；meta 不可变、不写入验证结论）；
  - **条目 schema（闭合字段机器可执行）**：`{"id": 项号, "status": pass|n-a|unverified|fail, "closed": bool, "evidence": 文件引用, "basis": 依据引用, "approval": 三方认可引用, "ts": ISO时间}`；`basis`/`approval` 在 schema 层可省略，但**是否必填由 `status` 决定**（按下方「状态必填条件」表机器判定）；缺任一必填字段 → `closed` 必须为 false（未闭合）。
  - 运行时记录目录：`docs/planning/evidence/o-stage/runtime-5.0.0-i1/`（各探针输出副本 + **`dmabuf-aggregate.txt`（R3+R6 聚合运行 stdout+stderr 整体落盘，§1.2 契约第 4 点）** + run-test-results.txt + install-rollback.txt，与阶段二证据路径分开、不可互相替代）。
- **必填条目清单（缺任一条目 = 未闭合，不得签发）**：`R1`…`R9`（R3、R6 为**两个独立条目**）、`U1`、`U2`、`install-rollback`、**`o-stage-integrity`**。
- **`o-stage-integrity` 条目（O_stage 整体验收；codex 阻断项 3 定义）**：R3+R6 那一次 `--iterations 5` 聚合运行中，**除 R3/R6 权威行以外的全部子项**归本条目。

  - `id`：`o-stage-integrity`
  - **来源权威行**（全部取自同一次运行落盘的 `dmabuf-aggregate.txt`，行号引用；夹具命名空间输出无效，§1.2 契约第 5 点）：

    | 子项 | 权威行（`run-dmabuf-regression-test.sh` 行号） | 计入 pass 的条件 |
    | --- | --- | --- |
    | invisible read | `dmabuf_invisible_read=PASS reason=iterations=5-size=…-max_read_munmap_ms=…-limit_ms=…`（:500） | `=PASS` |
    | write-readback | `dmabuf_write_readback=PASS reason=iterations=5-size=…-verify=5-pages=…`（:515） | `=PASS` |
    | topology / active vblank | `dmabuf_vblank_active=PASS reason=active_crtcs_tested=<N>-all-ok-samples=…-per_crtc=…`（:663）；无 active CRTC → `=UNVERIFIED reason=no_active_crtc`（:765） | `=PASS`；`no_active_crtc` → 走 unverified 合并 |
    | 设备身份 | `dmabuf_device=ok render=… card=… bdf=… (1ec8:9810)`（:188） | `=ok` |
    | 状态快照（8 字段） | `dmabuf_status=ok`（:795）/ `dmabuf_status=fail reason=…`（:241/:797） | `=ok` |
    | 内核日志门禁 | `dmabuf_kernel_log=clean`（:838）/ `=SKIP reason=dmesg_unavailable`（:841）/ `=UNVERIFIED reason=…`（:837）/ `=fail reason=…`（:836） | **仅 `=clean`**。`=SKIP reason=dmesg_unavailable` → **走 unverified 合并，不计入 pass**（脚本语义：pre 快照不可用 → `KLOG_OK=0`+`KLOG_UNAVAILABLE=1`（:299）→ 必使 `overall=UNVERIFIED reason=kernel_log_unavailable` + rc=3（:867-870），故 SKIP 不可能与 overall=PASS/rc=0 共存）；`=UNVERIFIED` → unverified；`=fail` → 规则 1 |
    | 子项计数 | `tests_total=… tests_passed=… tests_failed=0 tests_skipped=… tests_unverified=…`（:844） | `tests_failed=0` |
    | 整体 | `dmabuf_regression_overall=PASS reason=…`（:873）+ 进程 rc | `=PASS` 且 rc=0 |

  - **合并规则（机器可判定；自上而下，命中即定 status，不再下探）**：
    1. 出现**任一** fail 级权威行——`=FAIL` 或 `=fail`（含 `dmabuf_self_import=FAIL`、`dmabuf_vblank_inactive_guard=FAIL`、`dmabuf_invisible_read=FAIL`、`dmabuf_write_readback=FAIL`、`dmabuf_vblank_active=FAIL`、`dmabuf_status=fail`、`dmabuf_kernel_log=fail`、`dmabuf_device=fail`、`dmabuf_tool=fail`、`dmabuf_regression_overall=FAIL`）——**或** rc∈{1,5} → `status=fail`、`closed=false`（**阻塞签发**）；
    2. 否则出现**任一** `=UNVERIFIED` 行（含 `dmabuf_kernel_log=UNVERIFIED`、`dmabuf_vblank_active=UNVERIFIED reason=no_active_crtc`）、**或** `dmabuf_kernel_log=SKIP reason=dmesg_unavailable`（:841，恒伴随 `overall=UNVERIFIED` + rc=3，:867-870）、**或** rc=3 → `status=unverified`、`closed=true`（记录即闭合；观察期内出现对应异常症状 → 转 fail、closed=false）；
    3. 否则 `dmabuf_regression_overall=SKIP` **或** rc=2（含参数/夹具/工具/编译错误，:21 退出码口径）→ `status=fail`、`closed=false`——真机批未取得验证证据，**不得**降级记为 unverified 掩盖。判定以 **rc + fail 行**为准：rc=2 的早退路径（:118/:123/:303/:328/:332 等）可能**根本不输出 overall 行**，只输出 `dmabuf_tool=fail`/`dmabuf_device=fail` 后 exit 2，此时仍按本规则判 fail。**`dmabuf_kernel_log=SKIP` 不属于本规则**（它恒为 rc=3，由规则 2 处理）；
    4. 否则（`overall=PASS` 且 rc=0 且 `tests_failed=0` 且无 fail/UNVERIFIED 行）→ `status=pass`、`closed=true`。
  - **两种 `SKIP` 语义不可混用（机器判定消歧）**：本方案出现两处 `SKIP`，脚本级语义**不同**，不得按字面统一处理：

    | 权威行 | 脚本机制 | 对 overall/rc 的影响 | 归属判定 |
    | --- | --- | --- | --- |
    | `dmabuf_vblank_inactive_guard=SKIP reason=no_inactive_crtc`（:770） | 经 `record_skip`（:352）→ 计入 `tests_skipped`，**不计入** failed/unverified | **不降级** overall（:871-873 只检 failed/unverified；注释即「SKIP 不阻止整体 PASS」），可与 overall=PASS/rc=0 共存 | **R6 → `n-a`**（§四 n-a 条件）；本条目仍可为 pass |
    | `dmabuf_kernel_log=SKIP reason=dmesg_unavailable`（:841） | **裸 echo**，不经 `record_skip` → 不计入任何计数 | **恒**伴随 `overall=UNVERIFIED reason=kernel_log_unavailable` + rc=3（:867-870），**不可能**与 overall=PASS/rc=0 共存 | **本条目 → `unverified`**（规则 2），**不计入 pass** |

  - `evidence`：`runtime-5.0.0-i1/dmabuf-aggregate.txt` + 本条目引用的各行号；`basis`：上表权威行 + 合并规则；`approval`：仅当 `status≠pass` 时必填（三方认可记录引用）。
  - **是否阻塞签发：是。** 本条目必须纳入上述状态机并 `closed=true`；`status=fail` → 阻塞；条目缺失 → 视为未闭合 → 不得签发。
  - **与 R3/R6 的关系（不可互相替代）**：`o-stage-integrity`、`R3`、`R6` 是同一次运行产出的**三个独立条目**。`o-stage-integrity=pass` **不得**推导 R3 或 R6 通过；`R3=pass` 也**不得**推导 `o-stage-integrity` 通过；整体行与 rc **不直接替代**任一单项结论。反向约束：R3/R6 权威行同时参与本条目的规则 1 fail 合并——即任一单项 FAIL 必使本条目 fail，杜绝「单项 fail 但整体验收记 pass」的漏洞。
- **状态必填条件（每类）**：
  - `pass`：closed=true + evidence（探针输出引用）；
  - `n-a`（**三类来源，通用条件一致**）：closed=true + evidence + **basis** + **approval**（三方认可记录引用）——**四项缺任一项即视为未闭合**（closed 必须置 false）：

    | n-a 来源 | basis（必填依据权威行/证据） |
    | --- | --- |
    | **R6**：无 inactive CRTC | 聚合输出 `dmabuf_vblank_inactive_guard=SKIP reason=no_inactive_crtc` 行（`run-dmabuf-regression-test.sh:770`；落盘文件 `dmabuf-aggregate.txt` 行号）。**禁止**以整体 `dmabuf_regression_overall=PASS` 推导 R6=pass（:871-873 SKIP 不降级整体）；也**禁止**把 SKIP 记为 fail |
    | **R7**：实机无 DDCCI 面板 | §1.2「R7-R9 证据格式」输出：全部 connector 均 `ddcci-props=none` 且 backlight 关联表无 DDCCI 面板条目 |
    | **R8**：实机无 2880x1800 外接面板 | §1.2 connector mode 枚举输出中无 `2880x1800@*` 模式行（含全部 connector 的 connected/disconnected 状态行） |

  - `unverified`（U1/U2/R9 观察项，以及 `o-stage-integrity` 经合并规则 2 判定为 unverified 时）：closed=true + evidence（观察记录；`o-stage-integrity` 取 `dmabuf-aggregate.txt` 行号引用）+ basis（`o-stage-integrity` 必填 = 合并规则 2 命中的权威行）——**记录即闭合**；观察期内出现对应异常症状 → status 转 fail、closed=false（阻塞）；
  - `fail`：closed=false（阻塞签发）；
  - 未闭合 = closed=false（任何状态缺必填条件均视为未闭合）。
- **「全 PASS」定义（机器可判定）**：所有条目 closed=true 且无 status=fail；n-a 与 unverified 在满足上述必填条件时属于闭合状态。
- 签发前提 = validation-results 全 PASS（按上述定义）+ 三方一致 + dsh 终审 + 用户批准。

## 五、执行纪律

- 保护区零写入；vendor/debs/patches 只读；无 tag 操作；
- 不安装契约仅由验证阶段受监督手动突破（安装/回退均记录操作者与时间戳）；

- 任何 fail → 停止并三方裁决，不得带病继续。
