### 1.2 真机 runtime（逐项：命令 / 判定 / 依赖 fixture）

真机前置（**两项均为硬前置**）：

1. **C3 裁决门已闭合**（§二 步骤 0.2）——C3 未裁决不得进入真机批；
2. **受监督安装 5.0.0-i1 包**（§二顺序；fantgpu 与 innogpu 模块互斥绑定同一 PCI 设备，runtime 探针必须在 5.0.0-i1 安装加载后执行）。

**固件加载确认（步骤 3 的早期中止判据；v4 新增，因 C3 第一层而设）**：模块加载后、跑任何 R 项**之前**，必须先确认固件实际加载成功——否则 C3 第一层推断成立时会得到一串无法归因的 FAIL 并浪费受监督安装/回退窗口。判据（全部需落盘）：

- `modinfo -F firmware fantgpu.ko` 输出的声明路径清单（预期含 `fantgpu/fh2m/fh2m.fw`、`fantgpu/fh2m/fh2m.sh`）；
- 对每条声明路径检查 `/lib/firmware/<路径>` 是否**实际存在**（预期：C3 未修复时全部缺失）；
- `dmesg` 中固件请求结果行（成功加载 / `request_firmware` 失败 / 超时）；
- 设备是否进入 ACTIVE（`/proc/driver/fantgpu/gpu00/status` 的 Driver/Firmware 状态字段，即 R3/R6 聚合入口所读的同一状态源）。

**中止规则（codex 初审 P1-2 修正：不引入第五态，改由独立 abort 证据承载）**：

四态状态机 `pass|n-a|unverified|fail` **不新增第五态**——它描述的是「**已执行**检查的结论」，而中止情形下 R 项**根本未执行**，塞进任一现有态都会污染语义（记 `fail` 会把载荷缺陷误归因为 030 链运行时缺陷；记 `n-a` 会与「面板不存在」类 n-a 混淆；记 `unverified` 会「记录即闭合」从而放过阻断）。故中止按下列契约处理：

1. **不创建、不填充** `5.0.0-i1-validation-results.json`——**不生成任何** R1-R9 / U1-U2 / install-rollback / `o-stage-integrity` 条目。§四「必填条目清单」的适用前提是**真机批实际执行**；中止时该清单不适用，签发因「无 validation-results 文件」而**天然阻断**（fail-closed，无需额外规则）；
2. 改由**独立中止证据**承载：`docs/planning/evidence/o-stage/runtime-5.0.0-i1/c3-firmware-abort.txt`（格式见下）；
3. **不存在混合态**：固件确认位于 §二 步骤 3、在**任何 R 项之前**（R 项自步骤 4 起），故中止时不会有部分执行的 R 项，也不会出现「部分条目已填、部分未填」；
4. rollback 恢复安装前状态（步骤 7 的恢复验证照常执行并记录到 `install-rollback.txt`）；
5. 实测结果回填 C3 作为裁决证据 → C3 第一层由「强推断」升级为「真机证实」。

- **变的是 deb**：载荷修复必然改变 deb 字节 → 新包 SHA → **新增 build 证据文件**（如 `build-5.0.0-i2.sha256`，与既有 `build-5.0.0-i1.sha256` **并存不覆盖**）；版本号若递增，builder 走新版本分支并重跑双构建字节一致。
- **validation-results 新增独立的包 provenance 字段**（与 `materialize_meta_sha256` **并列，不是替代**）：`package_version` + `package_deb_sha256` + build 证据文件引用 + 双构建一致性引用。两条绑定各司其职——`materialize_meta_sha256` 锁**内核源树** provenance，`package_deb_sha256` 锁**被安装的实际载荷**。
- **例外情形（非 C3-a/b 预期路径）**：若三方裁决 C3 修复必须改动 **O_stage 内核源树本身**，才构成**新的 materialize 五件事务** → 必须完整重新生成并校验五件产物 + 新建 meta（同代要么全在要么全无）。届时须**先参数化** `materialize-o-stage.sh`：当前产物名**硬编码** `P_META="5.0.0-i1.meta.json"`（`:70`）、版本固定 5.0.0-i1，无法直接产出其他版本的五件事务。
- 本方案中所有 `5.0.0-i1` 与 `20942b3d…` 引用在版本递增时同步指向新包。

### C3 F 血统内核与 O 血统固件/userspace 载荷不匹配（**阻断级**；v4 新增，真机批放行前必须先裁决）

**发现来源**：F 批（F1-F7 lineage 参数化）实现前的静态事实核查（qoder · 2026-09-11）。核查目标原为确认 fantgpu 血统权威命名，结果发现 5.0.0-i1 包存在**载荷血统错配**。

- `fantgpu-base-update-evaluation.md:203-220` 列出完整 loader ABI 命名分歧表，结论：「必须**协调的整栈替换，不允许混合稳态**」；`:225-238` 列出固件路径与 `.fw` 内容分歧。

## 五、执行纪律

- 保护区零写入；vendor/debs/patches 只读；无 tag 操作；
