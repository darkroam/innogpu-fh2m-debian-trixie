# 多 Agent 协作规约（dsh + codex）

> 建立于 2026-08-31 · 由用户确认生效 · 参考 clear-jlpt-n2 协作模式、按本仓库约束适配

本文是 dsh（监督）与 codex（实现者）在本仓库协作的唯一规约。其他文档只链接本文，
不复制规则。

## 一、角色分工

| 角色 | 职责 |
|------|------|
| 用户 | 提出要求、最终拍板；确认规约变更与重大决策 |
| dsh（监督） | 把要求整理成自包含提示词与验收标准；审查 codex 成果、给出裁决与问题清单；按 §七 批准 commit/push；维护审查结论与轮次索引 |
| codex（实现者） | 按提示词落实实现，交付可运行成果；有主动性：可提出更优方案、发现问题主动汇报 |

## 二、标准流程（每轮迭代）

1. 用户向 dsh 提出要求 → dsh 创建轮次 `collab/R{编号}-{YYYY-MM-DD}-{主题}/`，同时写入：
   - `request.md`：用户要求原文 + 完整提示词（本机私有目录，见 §五；凭据/密钥禁入）；
   - `report.md` 模板：固定节标题（做了什么/产出文件清单/验证结果/偏差及原因/遗留问题），
     状态占位 `待开发`；
   - 在 `collab/INDEX.md` 登记该轮（状态 `待开发`）。
2. 用户将提示词交给 codex 执行；codex 如有更优方案可主动提出，经确认后执行。
3. codex 完成后填充同目录 `report.md`（做了什么、产出文件清单、验证结果、与提示词的
   偏差及原因、遗留问题），并把 INDEX 状态更新为 `待审查`。
4. dsh 审查（需求符合性 / 质量 / 规范 / git）→ 问题清单写入 `report.md` → codex 返工或通过。
5. 审查通过后按本仓库 git 纪律提交（见 §七），提交说明由用户/监督定稿。

## 三、提示词规范（dsh 产出）

- **自包含**：写明背景、目标、具体任务、验收标准、约束，codex 无需追问即可执行。
- **明确边界**（三层，按此分级写入提示词）：
  - **绝对禁止**（任何情况下不可修改）：本地载荷 `debs/`、`vendor/`、`build/`、
    `third_party/`，以及监督分支 `migration/supervised-source-tree`。
  - **默认保护**（默认不可修改；仅当用户在提示词中明确批准**精确路径范围**后才可改）：
    `drivers/`、`baselines/`、`binary-manifest.json`。
  - **自由范围**：其余文件，但须遵守仓库门禁（见 §六）。
- **明确交付物**：文件路径、格式、登记要求（新脚本/测试需同步 scripts/README、tests/README、
  test-strategy 与 project-tools allowlist）。
- 验收标准给足，但不限制实现路径；鼓励 codex 主动提出更优方案。

## 四、codex 主动性（实现者权限与义务）

- 收到提示词后，若认为有更优方案（工具选型、分批策略、产出结构等），可主动提出替代方案并
  说明理由，经确认后执行。
- 执行中发现提示词有误、素材缺失、或需求与实际冲突，主动汇报，不闷头硬干。
- 遇阻塞或重大偏差，及时汇报进展与影响面。
- 汇报内容须包含：做了什么、产出文件清单、验证结果、与提示词的偏差及原因、遗留问题。

## 五、合作目录存档（`collab/`）

- 位置：仓库根目录 `collab/`（英文目录名；唯一外层目录，所有轮次子目录收于其下，根目录不
  散放）。**本机私有目录**：已加入 `.gitignore`，不上传 GitHub、不参与任何公开分发。
- 结构：`collab/R{编号}-{YYYY-MM-DD}-{主题}/`，创建轮次时即含 `request.md`（用户要求原文 +
  dsh 提示词，本机私有）与 `report.md` 模板（codex 汇报 + dsh 审查结论）、可选附加 `.md`
  交付物；**轮次目录内只允许 Markdown 文件**（禁止二进制、代码快照等非约定文件，机械强制）。
- 索引：`collab/INDEX.md` 记录每轮 轮次/日期/主题/状态（状态 ∈
  待开发/开发中/待审查/通过/返工/已提交/执行中），与轮次目录按编号**双向一一对应**。
- **许可与发布边界**：`collab/` 本机私有、不入 Git，因此不是公开分发面；仍**排除出
  project-tools 候选制品**（denylist `^collab/` 防御性保留），不自动认定任何许可证；
  轮次记录中**不得出现凭据、token、私钥或机器身份**（隐私扫描覆盖 collab/），其他信息
  可按需保存；任何内容若要离开本机（同步到文档、贴出汇报等），必须先脱敏并经隐私审查。
- 机械校验：目录命名（`R{编号}-{日期}-{主题}`）、编号唯一、request.md/report.md 齐全（模板
  在创建时即生成）、INDEX 登记与合法状态、仅 Markdown 文件、INDEX 与目录按编号**双向一一对应**
  （精确匹配编号、日期与主题，R01 不误配 R010；重复行/孤立行/孤立目录/根目录或内部符号链接/
  嵌套目录均拒绝；INDEX 与隐藏 Markdown 同样纳入大小写无关的隐私扫描），由
  `tools/validate-collab.py` 执行、`scripts/check-docs.sh` 强制（collab/ 不存在时视为无轮次，
  直接通过）；fixture 见 `tests/unit/run-collab-structure-tests.sh`。

## 六、审查标准与仓库门禁（本仓库专属）

- [ ] 验收标准逐条核对通过。
- [ ] 无越界改动：§三 的绝对禁止项零改动；默认保护项仅在用户批准的精确范围内改动。
- [ ] **CI/沙箱测试入口**全部 PASS，且 test-strategy.md 计数与实际一致（"全部测试入口"指
  test-strategy.md 列出的 CI/沙箱入口，不含需真实设备/root/副作用的 runtime/授权测试；后者仅当
  任务需要且用户在提示词中批准时运行）。文档-only 任务可按风险运行相关测试 + 固定门禁。
- [ ] `python3 tools/audit-licenses.py` → `license_audit_overall=PASS` 且
  `license_release_gate=BLOCKED` 保持（发布决策 1C）。
- [ ] `bash scripts/check-docs.sh` → `RESULT: PASS_DOCS`。
- [ ] `git diff --cached --check` 干净；隐私扫描无真实用户名/hostname/凭据/token/私钥/本机
  绝对路径泄漏；涉及 shell 时 `bash -n` 与 ShellCheck（error+warning）清零。
- [ ] 新增 tracked 文件已同步 allowlist（`--write-allowlists`）与文档登记；无未登记脚本/工具。

## 七、git 纪律（本仓库与参考项目不同）

- 本仓库默认**停在提交前**：dsh 与 codex 的产出均**不得自行 commit**。
- commit / push 仅在用户或监督明确批准后执行；**不创建 tag/Release**（发布决策 1C：当前不发布）。
- 每轮产出的报告必须明确仓库内产出的 staged / unstaged / untracked 状态与 HEAD/领先关系
  （collab/ 本机目录不入 Git，不参与状态说明）。
- codex 如需多步骤推进，通过 `collab/` 轮次目录或指定暂存状态交接，不借助未授权的提交。
